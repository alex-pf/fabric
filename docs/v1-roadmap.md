# План до версии 1 фабрики (v1 Roadmap)

Цель v1: **окружение продукта собирается фабрикой** — репозиторий + доска + автоматизация «задача в Todo → реализация». Примитивно: без дозапросов постановки (intake-уточнений), без обязательного ревью человека в продуктовом контуре. Human Review остаётся для задач самой фабрики.

Критерий готовности v1: человек заходит на доску продукта, описывает первую задачу, двигает в Todo — и задача сама идёт в реализацию (ветка → PR → зелёные проверки → merge → журнал).

## Фазы

### Фаза 0 — Фундамент фабрики ✅ / в работе

| Задача | Статус |
|---|---|
| #1 Зафиксировать пайплайн разработки фичи | ✅ (pipeline.md в main) |
| #2 Настроить CI: линт + тесты + сборка | Todo |
| #3 Защитить main: обязательный PR + зелёные проверки (rulesets) | Todo |
| #6 Граница фабрика/продукт (ADR) + план до v1 | In Review |

Фаза 0 закрыта, когда любое изменение в fabric идёт через PR с зелёными проверками (правило уже принято 24.11, доводим до автоматики).

### Фаза 1 — Сквозной спайк агента

| Задача | Статус |
|---|---|
| #4 Спайк: агент ведёт задачу с доски до PR end-to-end | Todo |

Проверяем вручную управляемым прогоном: агент берёт задачу с Fabric-доски, создаёт ветку и PR, проверки зелёные. Результат — пост в журнале: что сработало, что нет, метрики (human touch count, gate pass rate).

### Фаза 2 — Контур продукта

| Задача | Статус |
|---|---|
| #5 Создать репозиторий и доску G1 | Todo |
| Кандидат: повторить для g1 CI + rulesets по образу fabric | — |

### Фаза 3 — Автоматизация v1 (новые задачи, заводятся после фазы 1)

Кандидаты в бэклог, приоритет сверху вниз:

1. **Триггер старта задачи** — что двигает карточку из Todo в работу: webhook на движение колонки / расписание / команда. Открытый вопрос из pipeline.md, решение принимаем на данных спайка (#4).
2. **Автоматизация продуктового цикла Todo → PR** — агент-разработчик как сервис: берёт задачу с G1-доски, ветка, код, PR по шаблону, self-review комментарием (этапы 2–4 пайплайна без Human Review).
3. **Автоматический пост в журнал по прогону** — этап 8 пайплайна для продуктового контура.

**Финал фазы 3 = релиз v1.** Прогон-монтаж: создать на доске G1 первую продуктовую задачу, провести её по контуру без ручного вмешательства, записать метрики в журнал.

## После v1 (не входит в план, фиксируем направление)

- **Этап intake-clarification (аналитик):** агент связывается с автором задачи, уточняет требования, передаёт разработчикам. Механика — фабрика, правила вопросов — конфиг продукта (ADR-0001). Вместе с этим появляется конфиг-слой `.fabric.yaml` — до второго этапа фабрики он не нужен.
- Возврат Human Review в продуктовый контур — по данным метрик rework/gate pass rate из прогонов v1.
- Второй продукт — проверка переиспользуемости.

## Связь с ADR

Граница ответственности — [ADR-0001](decisions/0001-factory-product-boundary.md). Этот план следует ему: v1 строится без конфиг-слоя, граница фабрика/продукт видна в структуре репозиториев, конфиг-слой откладывается до появления второй фабричной фичи.
